# Roadmap 0.8 → 1.0: точечные инструменты, накапливающие состояние

> Design-doc, обновлён 2026-07-03 (v2: добавлен jobs-first принцип и план
> изменений репозитория по файлам). Основан на: критике методологии,
> gap-анализе реальной (приватной) инициативы автора, конкурентном анализе
> AI-инструментов для PM (2025–2026) и наблюдении, что даже автор использует
> пайплайн точечно, а не целиком.
> Рабочий язык документа — русский; при финализации релизов ключевые части
> переносятся в README/CHANGELOG на английском.

## Два принципа редизайна

**1. Хребет инструмента — реестр гипотез и доказательств, а не номера шагов.**
Реальная работа PM вращается вокруг гипотез (опровергнута → разворот;
подтверждена REAL → переприоритизация). Шаг — способ добыть недостающее
доказательство. Фаза закрыта, когда доказательства собраны, а не когда шаги
«пройдены».

**2. Вход — через работы (jobs), а не через шаги. Пайплайн — бухгалтерия за
кадром.** Наблюдение: полный пайплайн не использует никто, включая автора;
живая работа — точечные действия («принесли дек», «нужен бриф», «завтра
защита»). Рынок подтверждает: успешны stateless-наборы скиллов и
однозадачные инструменты, полно-пайплайновых продуктов нет. Наш
дифференциатор — не «проведу по 20 шагам», а «каждое точечное действие
оставляет след в состоянии». Точечность — интерфейс; состояние — ценность.

Следствия: каждый job самоценен с первого вызова и работает без setup;
инициатива создаётся лениво («сохранить в инициативу?» после результата);
прогресс — карта покрытия доказательствами, а не «4/20 шагов»; полный проход —
один из сценариев, а не норма.

## 0.8 «Фундамент»

### E1. Реестр гипотез — машиночитаемое состояние (L) ✅ сделано

`output/hypotheses.json` — единственный источник истины о СОСТОЯНИИ гипотез
(статус, тип, confidence, источники, история). Нарративные markdown-файлы
остаются авторской аналитикой; генерируемое представление — `output/registry.md`.

> Решение по формату: JSON вместо YAML из роадмапа v1 — PyYAML не входит в
> стандартную библиотеку, а урок 0.7.x (краш SessionStart без `rich`) требует,
> чтобы ядро работало на голом python3. Нарратив не генерируется из реестра —
> живые реестры оказались богатой прозой, которую нельзя терять.

```json
{ "id": "H4", "title": "Пользователи бросают чекаут из-за недоверия к оплате",
  "status": "confirmed", "evidence_type": "REAL", "confidence": 0.7,
  "sources": [{"file": "research/analytics-data.md", "ref": "дашборд оплат, стр. 3"}],
  "history": [{"date": "2026-06-10", "change": "SYNTHETIC 0.3 → REAL 0.7"}] }
```

Критерии приёмки (выполнены): `registry.md` генерируется из JSON; REAL
невозможен без источников; переходы пишутся в history автоматически (`set`);
миграционный скрипт сконвертировал реальный реестр автора (13 гипотез),
валидатор нашёл известный дефект (confidence вне диапазона REAL).

**Изменения в репозитории:**
- NEW `tools/scripts/hypotheses.py` — add/set/validate/render/show
- NEW `tools/scripts/migrate-hypotheses.py` — конвертация legacy md → JSON
- NEW `template/output/hypotheses.json` (пустой, `_schema` с описанием полей)
- MOD `.claude/skills/pipeline-steps/SKILL.md` — шаги 1/2/6/7 ведут реестр
- MOD `.claude/rules/evidence-typing.md` — реестр как носитель типов

### E2. Evidence ledger и валидаторы (M) ✅ сделано

Валидация на SessionStart: confidence в диапазоне типа; у REAL есть источник;
флаг `data_inconsistency` ставится при обнаружении противоречия источников
(`set --flag`), и пока он стоит, confidence >0.6 — нарушение, о котором аудит
напоминает каждую сессию; сводка «N confirmed REAL / open / refuted / flagged».

> Уточнение против v1: автодетекция расхождения «>10%» невозможна без
> структурированных метрик — флаг ставится осознанно в момент обнаружения
> противоречия, а инструмент принуждает к последствиям (кап confidence,
> напоминание каждую сессию, история установки/снятия).

Критерии приёмки (выполнены): прогон на реальной инициативе автора находит оба
известных дефекта (confidence вне диапазона REAL; несверенная метрика двух
страниц дека) без ложных срабатываний.

**Изменения в репозитории:**
- NEW `tools/scripts/validate-evidence.py`
- MOD `tools/scripts/hypotheses.py` — `set --flag/--unflag`
- MOD `.claude/settings.json` + `template/.claude/settings.json` — хук
- MOD `.claude/rules/evidence-typing.md` — операционные правила

### E3. Digest, статус и константы — производные от реестра (M) ✅ сделано

Digest собирает вердикты из реестра («✅ REAL: … · ❌ … · открыто: N ·
⚠️ flags: …») вместо только regex-парсинга CONTEXT.md; прогресс считается от
включённых шагов; единый модуль констант убрал 4 разъехавшиеся копии списка
шагов (fallback-итоги были 18 vs 19 vs 21; app.py не знал шага 0; status.py
не доходил до шага 19). Попутно найден и починен пре-существующий
SyntaxError в app.py (f-string с backslash — дашборд не стартовал на
Python < 3.12).

**Изменения в репозитории:**
- NEW `tools/scripts/pipeline_constants.py` — шаги/лейблы/фазы/хелперы
- MOD `tools/scripts/status.py`, `tools/scripts/scan-initiatives.py`,
  `tools/web/app.py`, `tools/web/static_export.py` — импорт констант,
  digest из реестра

  `.claude/skills/user-test-concept/SKILL.md` — добавлен frontmatter

## 0.9 «Jobs-first и петли»

### E6. Zero-setup и ленивая инициатива (M) ✅ сделано

### E8. Внешние зависимости с SLA (M) ✅ сделано

/ перейти на синтетику (с даунгрейдом зависимых гипотез) / осознанно скипнуть.

```json
  "id": "analytics_funnel_split",
  "kind": "analytics",
  "owner": "аналитик команды",
  "jira": "ANLT-123",
  "created": "2026-06-10",
  "deadline": "2026-06-17",
  "blocks": ["H5", "H6"]
}
```

**Изменения в репозитории:**

### E9. `/ingest` — первоклассный приём внешних данных (L) ✅ сделано

`/ingest <файл|Confluence pageID|URL>`: парсинг (PDF/xlsx/csv/Confluence) →
извлечение метрик с привязкой к месту («слайд 12: CTR по surface X ≫ Y») →

Критерий приёмки: прогон на реальном внутреннем деке из инициативы автора
воспроизводит сделанный вручную июньский результат за один вызов.

## 1.0 «Карта и гейты»

### E11. Карта покрытия вместо трека фаз (L)

Семь фаз (Frame → Evidence → Solution → Bet → Build → Launch → Learn) — не
маршрут, а **диагностическая карта**, вычисляемая из реестра и зависимостей:
«Frame: цель не зафиксирована ⚠️ · Evidence: 3/4 · Solution: пусто». Переходы
разрешаются доказательствами, а не порядком. Прогресс инициативы = покрытие,
«N/20 шагов» умирает.

**Изменения в репозитории:**
- MOD `tools/scripts/pipeline_constants.py` — определение фаз и exit-критериев
- MOD `tools/scripts/status.py`, `tools/web/app.py` — отображение карты
- MOD `template/output/status.json` — v2: блок phases (derived), миграция
- DEL понятие pipeline_template из CLAUDE.md и скриптов

### E12. Гейты как рубиконы + `/challenge` (M)

Preconditions (машинные, из валидатора E2): Gate 1 требует ≥2 confirmed REAL,
0 data_inconsistency, зафиксированный target — иначе сборка презентации
блокируется. Исходы pass/partial/fail с автозаписью в decisions.md.
`/challenge` — адверсариальная репетиция: «злой стейкхолдер» (CFO / VP /
скептик-инженер) атакует презентацию по реестру. Флагманская фича релиза.

**Изменения в репозитории:**
- NEW `.claude/skills/challenge/SKILL.md`
- MOD `.claude/skills/pipeline-steps/SKILL.md` — preconditions и исходы гейтов
- MOD `tools/scripts/validate-evidence.py` — режим `--gate`

### E13. Opportunity Solution Tree из реестра (S)

Из `hypotheses.yaml` генерируется OST (mermaid + html в `output/`): outcome →
проблемные гипотезы (цвет по evidence_type) → решения → эксперименты.

**Изменения в репозитории:**
- NEW `tools/scripts/render-ost.py`
- MOD job `/hypotheses` и `/validate` — предлагают перегенерацию дерева

### E14. Фаза Learn: закрытие петли и knowledge base (M)

`/post-launch-review` (по deadline-зависимости «проверить через 90 дней»):
факт vs target; вердикты гипотезам в production. `knowledge/facts.yaml` на
уровне PM — выученные бенчмарки с источником и датой; новые инициативы
подтягивают релевантные факты на старте; калибровка «наши INFERRED
подтверждаются в X% случаев» из history реестров.

**Изменения в репозитории:**
- NEW `.claude/skills/post-launch-review/SKILL.md`
- NEW формат `knowledge/facts.yaml` — папка личная, автоматически игнорируется
  whitelist-правилом `.gitignore` (в репо — только описание формата в docs/)
- MOD `tools/scripts/scan-initiatives.py` — подтягивание фактов в digest

## Чего не делаем (анти-скоуп)

- Не наращиваем генерацию документов — ниша коммодитизирована.
- Не добавляем шагов — номенклатура сжимается в ~9 jobs.
- Не тащим данные в облако — локальность остаётся принципом и аргументом.
- Не делаем мультиюзерность — веб-дашборд остаётся локальным просмотрщиком.

## Как валидируем

Каждый эпик — dogfood-прогоном на реальной (приватной) инициативе автора:
E1/E2 находят известные дефекты её реестра; E9 воспроизводит сделанный вручную
ingestion внутреннего дека; E8 поднимает реально зависшие внешние зависимости;
E7 отвечает на «что дальше?» лучше, чем таблица шагов; E12 репетирует реальный
Gate 1.

## Порядок и зависимости

```
E1 ──► E2 ──► E3 ──► (0.8) ──► E5 ──► E6 ──► E7 ─┐
 │                              │                ├─► (0.9) ──► E11 ──► E12 ──► (1.0)
 │                              └──► E8 ─────────┤              │
 └───────────────────────────► E9 ──► E10 ───────┘        E13, E14 — после E11
E4 — параллельно всему 0.8
```

Критический путь: E1 (реестр) — без него не строятся ни валидаторы, ни jobs
с накоплением состояния, ни карта покрытия. E5/E6 (jobs-first вход) — самый
большой UX-сдвиг, делается сразу после фундамента, до гейтов.
