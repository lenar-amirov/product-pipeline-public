# Cleanup 1.3 «Прунинг»: репозиторий = манифест

> Design-doc, 2026-07-04. Сведение двух аудитов: файловой инвентаризации
> (необходимость каждого файла, потребители проверены) и смыслового среза
> (соответствие частей манифесту инструмента).

## Принцип

Манифест инструмента после редизайна 0.8–1.2: **точечные jobs, накапливающие
честные доказательства в реестре; карта покрытия; настоящие гейты; закрытие
петли; локальность данных**. Всё, что противоречит манифесту, дублирует его
или существует «для полноты», — удаляется. Репозиторий и его философия
должны совпадать на 100%: это публичный продукт, и каждый лишний файл — налог
на доверие форкающего.

Диагноз аудитов: ~70 файлов тянут свой вес (потребители подтверждены);
лишнее сосредоточено в пяти зонах.

## P1. Template: смерть контентных заглушек (S)

**Что**: удалить 19 заглушек — 13 в `template/output/` (ab-test-analysis,
ab-test-design, design-brief, gate2-presentation, gtm-materials, gtm-plan,
hypotheses.md, presentation, solution-hypotheses, solution-sketch, tickets,
ux-research-brief, validated-hypotheses) и 6 в `template/research/`.

**Почему**:
1. Заглушки создают баг false-exists: веб-просмотрщик считает артефакт
   существующим при size > 0 (app.py:251) — пустышка на 8 строк
   отображается как готовый артефакт.
2. Jobs-first: файлы создаются jobs в момент работы; форматы канонизированы
   в `output-formats.md` и скиллах — заглушка это третий дубль формата.
3. Живой gap-анализ показал: заглушки месяцами лежат пустыми и создают
   иллюзию структуры.

**Остаётся в template (10 файлов)**: CONTEXT.md, output/status.json,
output/hypotheses.json, output/PRD.md (скелет секций — заполняется
инкрементально), output/decisions.md, output/design-comments.md
(единственная PM-facing форма), .claude/settings.json, три .gitkeep
(CJM создаётся скриптом; html/, materials/, screens/ нужны рендерам).

**Попутные фиксы**:
- `ux-research-brief.md`: единый путь `research/` (user-testing прав;
  поправить steps.md STEP 11, убрать output-заглушку).
- `template/slides/*.pptx.pdf` в STEP 10/15: переформулировать из мёртвой
  ссылки в явную опцию — «положи корпоративный шаблон в `template/slides/`
  — подхватится».

**Приёмка**: `new-initiative.sh` создаёт инициативу из 10 файлов; веб и
карта покрытия показывают отсутствующие артефакты честно.

## P2. Веб-просмотрщик: только просмотр (M)

**Что**:
1. Удалить `templates/new.html` + create/upload-роуты app.py (~80 строк).
2. Удалить share-механику: `shared_artifact`, `_find_shared`, токены

**Почему**: веб-форма создания инициативы — ровно тот анкета-upfront
анти-паттерн, который FIRST LAUNCH убил (инициатива рождается лениво из
чата, с реестром и jobs-контекстом; форма создаёт её мимо всего этого).
Share-ссылки — зачаток мультиюзерности из анти-скоупа: на 127.0.0.1
бессмысленны, на 0.0.0.0 опасны (аутентификации нет); путь шеринга —
zero-dep `static_export.py`.

**Приёмка**: app.py — read-only просмотрщик (дашборд, инициатива,
артефакты, архив); README обновлён; grep по new/share-роутам пуст.

## P3. consulting-problem-solving: интеграция по органам (M)

**Что**: не выносить целиком, а пересадить уникальные органы в наши
структуры и удалить дублирующую оболочку. Его 8 стадий — параллельная
вселенная нашего же цикла (define↔FIRST LAUNCH, MECE↔problem-structuring,
analyze↔/validate, communicate↔strategic-narrative …) — но три вещи
уникальны и потребляемы:

1. **`writing-style.md`** (Strunk & White) → `.claude/rules/writing-style.md`;
   пункт в anti-generic self-check: «прогони прозу артефакта по
   writing-style». Потребители — все генераторы документов (PRD, нарратив,
   брифы, GTM).
2. **`mckinsey.md` + `08-communicate.md`** (storylining, структура деков,
   «so what») → `strategic-narrative-generator/references/` с указателем
   «читай при сборке гейт-презентации» — прогрессивное раскрытие, вес
   грузится только при работе над деком.
3. **Партнёрская модель взаимодействия** → новый тонкий job **`/deep-think`**
   (~40 строк): фасилитируемая сессия структурного мышления для проблем,
   которые ЕЩЁ НЕ инициативы (стратегические/организационные вопросы без
   метрики). PM ведёт, Claude исполняет; движки — наши (problem-structuring
   для дерева, narrative-references для итога); финал — мост «превратить в
   инициативу? → Frame + /hypotheses». Не 8 своих стадий, а оркестрация
   существующих. Jobs-каталог в CLAUDE.md растёт до 10.

**Удаляется**: оболочка SKILL.md и references 01–07 (define, structure,
prioritize, work-plan, analyze, synthesize, recommend) — дублируют
пайплайн. Из ~1360 строк выживает ~400 — там, где они реально потребляются.

**Приёмка**: consulting-папки нет; writing-style в rules и в self-check;
narrative-references читаются из strategic-narrative-generator; `/deep-think`
в JOBS CATALOG и работает без инициативы; problem-structuring больше не
ссылается на consulting.

## P4. Step 18: фабрика GTM-материалов → Optional и сжатие (S)

**Что**: тип Recommended → Optional (в `pipeline_constants.py` смысловой
нагрузки нет — тип живёт в template status.json `pipeline_config` и
steps.md); сжать инструкцию с «10 файлов, включая press-release» до
«канал из GTM-плана → 1 готовый артефакт по запросу PM».

**Почему**: анти-скоуп продукта — «не наращивать генерацию документов,
ниша коммодитизирована». Exit-критерии фазы Launch (карта покрытия):
gate2 + решение по эксперименту + GTM-план; материалы в них не входят.
Press-release для корпоративного PM — наследие «полного пайплайна».

**Приёмка**: steps.md STEP 18 ≤ 25 строк; template status.json:
`create_gtm_materials: optional, enabled: false`.
