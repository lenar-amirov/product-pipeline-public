# One Path 1.4 «Один путь»: смерть плагин-контура + старт за 60 секунд

> Design-doc, 2026-07-06. Решение владельца: один канал дистрибуции.
> Основания: плагин — обёртка вокруг «скопируй файлы» (Claude Code не
> подгружает CLAUDE.md плагина в проект пользователя, init всё равно копирует
> файлы); автообновления marketplace не достигают заскаффолженных проектов —
> главное обещание формата здесь иллюзия; заскаффолженные проекты
> самодостаточны, удаление контура не ломает ни одного пользователя; цена
> содержания — 222-строчный инсталлятор, два манифеста, version-bump в каждом
> релизе и дважды случившийся рассинхрон (чинили в 1.0.1).

## Цель

**Один путь. TTFV ≤ 60 секунд**: от «услышал об инструменте» до первого
полезного артефакта — одна команда в терминале и одно сообщение в чате.

```bash
git clone https://github.com/lenar-amirov/product-pipeline-public.git pm-copilot
cd pm-copilot && claude
# → «What product problem are you working on?» — просто ответь
```

Риск, принятый осознанно: marketplace как канал обнаружения. Обратим —
тонкий плагин возвращается за день, git всё помнит.

## S1. Удаление плагин-контура (S)

- DEL `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`
- DEL `skills/init/SKILL.md` (папка `skills/` исчезает целиком)
- `.gitignore`: убрать `!/.claude-plugin/` и `!/skills/` из whitelist
- `tools/scripts/check-leaks.py`: убрать `.claude-plugin` из TOOL_DIRS
  (папки больше нет — запись стала бы немой)

**Приёмка**: дерево 79 → 75 файлов; `grep -ri "plugin\|:init"` по коду и
скиллам пуст.

## S2. README: клон — парадный вход (S)

- «Get started in 30 seconds» переписывается: **(1)** clone+claude (3
  строки, ноль вопросов, ноль рестартов) · **(2)** «без git» — Download
  ZIP → распаковать → `claude` · **(3)** обновления — `git pull`
  (заметка: перед pull — `git stash` своих правок CLAUDE.md, или форк).
- Удалить секции `/plugin marketplace add`, `/plugin install`,
  `/product-discovery:init` и все упоминания плагина.
- После установки — блок «что произойдёт»: welcome-экран + пример
  «ты пишешь → получаешь» (обезличенный, по anti-generic правилам).
- Сравнительная таблица «vs toolboxes» остаётся — она про суть, не про
  дистрибуцию.

**Приёмка**: путь установки в README — один, короче 10 строк.

## S3. Welcome-экран продаёт jobs (S)

`tools/scripts/status.py` (render_onboarding + render_plain, ветка без
.pm-local): после «What product problem are you working on?» добавить:

```
  Или сразу точечно:
    «прочитай этот дек»        → /ingest
    «нужен бриф аналитику»     → /brief
    «разложи проблему X»       → /hypotheses
```

Позиционирование (точечность) сообщается в момент первого контакта; PM с
деком в руках получает ценность первым сообщением, минуя формулирование
«проблемы».

**Приёмка**: свежий клон без .pm-local показывает примеры jobs в обоих
режимах (rich и plain).

## S4. Версионирование — только CHANGELOG (S)

plugin.json был вторым носителем версии и источником рассинхрона. После S1

## Порядок и смоук

S1 → S2 → S3 → S4+S5 одним релизом **1.4.0 «Один путь»**. Смоук: свежий
клон в чистую папку → `claude` → welcome с примерами jobs; все три хука;
`new-initiative.sh`; grep-зачистка; push через leak-guard.

## Чего НЕ делаем

- Не переделываем init «для продолжения в той же сессии» — init умирает
  вместе с контуром, задача решается сама.
- Не добавляем инсталлятор-скрипт (curl | bash) — clone уже одна команда,
  а curl-пайпы в публичном инструменте подрывают доверие.
- Не выпиливаем `.github/` — issue-шаблоны остаются каналом обратной связи.
